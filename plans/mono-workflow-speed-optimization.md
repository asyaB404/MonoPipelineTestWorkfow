## 目标

在保持原始用例语义、有效证据和 passed 判定质量的前提下，减少 Agent 编排空档、重复读取、重复准备和不必要的逐条调用。优先验证技能侧与执行编排的改进，不改父 Workflow，不以放宽门禁或把 blocked/test_inconclusive 改记为 passed 换取速度。

## 讨论中的实施阶段

1. **建立可比基线**：记录材料与用例摘要、Mono 包/build 标识、账号及关键业务状态、权限范围、实际使用的 Skill 提交/交付清单摘要。将端到端时间拆分为准备、Player 就绪、附加/共享链路、业务用例、收口/报告；另记 Agent 调用空档、命令数与类型、身份核验数、请求登记数、run-suite 批次数、重复读取及证据体积。
2. **精简说明结构**：由 SKILL.md 保留直线路径、不可违反的关键约束和按需文档路由；业务批次组织集中在 business-execution.md；命令/schema/证据规则集中在 host-contract.md。消除同一门禁、步骤和停止条件在多处重复叙述，保留 CyouCode 执行所需的短摘要与明确引用，不因文件体积删除仍被运行或验证依赖的资产、模板和测试。
3. **优化执行编排**：稳定路径采用一次 plan-check 后 run-suite 批处理；只在确有现场分支时单例探索。按真实账号状态、页面状态和前后置依赖分组，合并同一观察可覆盖的必要字段；每个用例仍独立证明自己的前置、交互及预期。避免每例读取与本例无关的全量事实，优先使用小范围、可复用的只读字段集合；不重发动作、不用跨例旧结果代替本例证据。
4. **CyouCode 对照验收**：以同一包和相同账号/资源/解锁状态下的相同用例集比较；若状态无法复现，则只比较同一可执行子集并标注差异。先由 CyouCode 验证新计划，不以 Codex 隔离测试替代公司 Agent 实测。

## 验收条件

- 可比用例集的 passed 绝对数不下降；不通过改写原用例、放宽比较或把未执行项记为通过来达成。
- 原前置、明确动作、动作后新帧及独立预期证据仍有效；failed、blocked、test_inconclusive 的归因不被省略。
- 端到端耗时、Agent 空档、每例重复读取、命令/身份核验数和证据体积均有前后记录；速度目标在当前实测基线明确后再设，不预先承诺固定百分比。
- CyouCode 能按文档独立完成，不需要 Codex 现场补齐关键判断。

## 范围与状态

本计划只讨论 Mono Pipeline Skill 和其执行编排。父 Workflow、Unity/PC 包、游戏业务代码、账号切换授权及测试质量门禁不在本轮默认变更范围。当前状态为讨论草案；当前 CyouCode 实机轮结束前，不修改其正在使用的 Skill 副本。是否开始实施、实施顺序及验收阈值由后续讨论确认。
