# GameClient 可选构建接线

类型化重载 = 通过明确的平台构建器接口传入本次实例的新增方法签名。公共四源不依赖本适配器；仅同框架目标在检查基线并另行批准后选择它。不同框架需要自己的原构建管线适配，不自动套用。

[`GlobalMonoPipelineGameClientBuild.cs`](GlobalMonoPipelineGameClientBuild.cs:1) 提供 Game Tools 新菜单、参数窗口、独立平台实例、临时设置快照和未压缩文件交付。匹配的增量在 [`framework-overloads.patch`](framework-overloads.patch:1)，包含原构建链三处重载及菜单分组别名，不含完整框架、旧测试路由或原工程业务。

接线顺序：核对并批准框架增量 → 将菜单源与元数据放入目标编辑器目录，并从同包接入公共四源 → 目标编译通过后，手动打开菜单，选择项目外新目录及端口，再单独确认构建。补丁只供人工评审/合并，不是自动安装命令；既有业务改动或未知基线必须保留。

菜单打开不构建。构建沿用原 App 版本、SDK、场景和资源生命周期，但新平台后处理不压缩、删除原包或准备上传。新输出包含静态包目录和包外真实构建库存，库存默认仍未批准完整游戏。构建结束恢复后端、宏、开发设置、代码生成选项和 HybridCLR 并保存资产；配置按原字节摘要恢复。原资源/版本/SDK 生成、域重载或强杀不承诺完整回滚。

旧测试宏在本次新构建中隔离，新服务仍要求 Windows Mono Development、新测试宏和显式启动开关。源码接入和 C# 定向编译不能替代完整包、真实监听/ACL、热更、截图、登录或业务验收。
