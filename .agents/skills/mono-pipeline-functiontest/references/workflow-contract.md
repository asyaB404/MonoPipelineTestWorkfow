## 适用范围

通常与 `functiontest-workflow` 一起使用；父流程、其公共子技能及既有方法均可参考和使用。父文件保持原样，PC 执行接入和差异说明仅维护在本技能，不将父文档缺少 PC 标题当成需要修父文件或停止测试的理由。直接调用仍可执行，不强迫另开父流程。

优先使用当前项目已部署的同套组件，按技能名定位实际目录并遵守相应 SKILL；外部参考包只读核对，不把个人绝对路径写成运行依赖，不跨副本混用脚本。父已完成的来源、生成和开关确认直接继承，不重复生成、询问、计时或上报；缺组件只影响相应阶段，完整用例就绪后可继续本地测试。

## 现有能力复用

| 阶段 | 复用组件与 Mono 接入边界 |
| --- | --- |
| 来源与用例 | `functiontest-workflow`、`testcase-gen`、`testcase-mcp-complete`；沿用实际选择及最终完整用例，不在 Mono 重写生成器 |
| 业务拆解与取证 | 可参考 `unity-functiontest` 的用例与证据方法；真实 PC 执行使用本技能，父示例中的编辑器编译、PlayMode、Unity MCP 和自修不变成 PC 默认动作 |
| 静态 UI 与视觉对比 | 按已确认开关复用 `ui-quick-reference` 的现有静态扫描/配置查询及 `ui-image-diff`；运行态从本次 Player 获取，不启动编辑器或调用 MCP；缺参考不减少业务覆盖，图像差异不自动改 verdict |
| 计时 | 复用 `functiontest-report-json` 的公共 `skill_timing.py` 和协议；父/子共用实际文件及编号，只由根过滤环境时间，不把子耗时相加 |
| 统计与用量 | `functiontest-report-json` 转换已生成的唯一报告，`check-cyoucode-spend` 读取实际快照，再按原合并接口处理；不复制解析或用量脚本，不猜模型/计时/身份 |
| 上传 | 仅在本轮明确外传许可及原门禁满足时使用 `functiontest-json-upload`；嵌套生成/参考子技能不单独上传，最终至多一次，不临时改上传器 |

这些是可复用的阶段，不要求每轮加载全部子技能；仅在当前任务实际需要时读取并使用其契约。父调用时继续沿用其控制权、输出路径和授权，父文件与子技能实现不因接入 Mono 被复制改造。

## 计时模式

| 模式 | 使用条件 |
| --- | --- |
| 与 Workflow 配合（常见） | 调用方已传入真实来源、范围与父/子起点；直接继承，不再次调用父技能、不另建包内父 |
| 直接执行 | 不传父绑定；使用本轮自身真实计时，直接 close/audit/report，不补造外部父记录 |
| 显式包内 parent | 使用原 `--parent` 与 `context-*`，仅在确有该模式需求时选择，不与 Workflow 父并用 |

父模式使用 [`init`](../scripts/cli.py) 的 `--workflow-timing`、`--workflow-parent-id`、`--workflow-child-id`：三项齐全、原记录尚未闭合、父技能必须为 `functiontest-workflow`、子技能为 `mono-pipeline-functiontest` 且归属准确。旧 PC 父记录仍拒绝，起点由实际计时器写入，宿主保留快照并重验；直接调用不要求这些参数，不让用户手填或伪造。

需要原统计目录时，output 指向允许的 `output/{feature_id}` 根，`--run-prefix` 为同一明确功能编号；实际本轮根仍为独占随机子根。独立本地调用可保留默认前缀和安全输出。[output-check](../scripts/cli.py) 先核验完整路径预算，超限仅在创建轮次前选许可内短根；既有冻结轮不换根重跑。

已有父模式的 writer 跨度仅为执行子阶段，不冒充整条父流程耗时；外部计时文件可正常追加/闭合，但原父/子起点与身份不能改写。独立模式没有父时间，不补造交接或扣减记录。

## 收口与验证

独立调用按 close → audit → report 生成唯一报告。已有父模式才先 close/audit、再闭合实际子/reference/父计时、最后 report；已绑定起点/身份改写、未闭合或包含关系错误仍拒绝，不能为了独立执行而撤销已登记父绑定。

外部来源/请求失效时仅能在私有证据有效的前提下本地诊断终止，不补 final，不正式报告、转换或上传；有父模式再结束实际父子计时，详见[来源中断](orchestration-recovery.md)。总数/四状态/问题数来自本轮审计，统计与上传分别服从本轮实际范围，本宿主不自行调用统计服务。

JSON 转换必须传 `--input` 为本轮 Mono 的明确 `functiontest-report.md` 文件，`--output` 为同轮明确 JSON 路径，并传实际公共 timing 文件、根 Skill 名和 invocation_id。现有转换器支持直接报告文件；传运行目录会寻找编辑器默认文件名，因此不传模糊目录、不复制改名报告，也不调用编辑器报告器重复渲染。输出已存在按原规则拒绝覆盖，真实缺 final 或不合格报告继续拒绝；真实全 blocked/全 test_inconclusive 保留本地结果并按原门禁跳过上传。

本技能验收覆盖自身执行、证据/结果、共享计时与实际公共转换接口复用；父 Workflow 文本分流检查只作参考，不以修改父文件换取通过。共享组件的隔离调用仍不证明 CyouCode 已完成真实业务验收，入口见[隔离验证](isolation-tests.md)。
