# 测试用例规范

## 字段定义

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `case_id` | string | ✅ | 用例编号，格式 `TC-{模块缩写}-{序号:03d}`，如 `TC-LOGIN-001` |
| `function_module` | string | ✅ | 功能模块，与测试要点一致 |
| `sub_module` | string | | 子模块，与测试要点一致 |
| `test_point` | string | ✅ | 对应的测试要点描述 |
| `title` | string | ✅ | 用例标题，格式 `[类型] 动词+对象+场景` |
| `description` | string | | 用例描述 |
| `preconditions` | list | ✅ | 前置条件列表 |
| `steps` | list | ✅ | 操作步骤列表，每步具体到操作对象和操作内容 |
| `expected` | list | ✅ | 预期结果列表，可量化验证 |
| `priority` | string | ✅ | P0/P1/P2/P3，与对应测试要点一致 |
| `risk_level` | string | ✅ | HIGH/MEDIUM/LOW，与对应测试要点一致 |
| `execution_type` | string | ✅ | POSITIVE / NEGATIVE / BOUNDARY |
| `confidence` | float | | 置信度 0~1 |

## 用例类型

| 类型 | 说明 | 生成要求 |
|------|------|----------|
| POSITIVE | 正向用例，正常输入预期成功 | 每个要点至少 1 条 |
| NEGATIVE | 异常用例，非法输入预期失败/报错 | 每个要点至少 1 条 |
| BOUNDARY | 边界用例，临界值测试 | P0/P1 要点至少 1 条 |

## 生成要求

1. 每个要点至少 1 正向 + 1 异常
2. P0/P1 要点至少 2 正向
3. 步骤具体到操作对象和操作内容（如"点击登录按钮"不是"点击按钮"）
4. 预期结果可量化验证（如"弹出提示'密码错误'"不是"显示提示"）
5. 用例编号格式：`TC-{模块缩写}-{序号:03d}`
6. 按优先级 P0→P1→P2→P3 排序输出

## 标题命名规范

- 正向：`[正向] 验证{功能}正常{操作}`
- 异常：`[异常] 验证{功能}在{异常条件}下的表现`
- 边界：`[边界] 验证{功能}在{临界值}时的表现`

## 优先级分布建议

| 优先级 | 占比 | 说明 |
|--------|------|------|
| P0 | ~15% | 核心流程 |
| P1 | ~35% | 主要功能 |
| P2 | ~35% | 次要功能 |
| P3 | ~15% | 边缘场景 |
