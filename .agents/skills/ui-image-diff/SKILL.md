# UI 图片固定控件差异对比

## Skill 时间记录（强制）

遵守 `../functiontest-report-json/references/skill-timing-contract.md`。开始读取和对比图片前记录 `skill_start`，报告落盘并完成校验后记录 `skill_end`。该 Skill 不产生 FunctionTest 测试统计，也不上传 FunctionTest JSON。

- 单独调用时，使用自己的 timing 文件，但仍不产生或上传 FunctionTest JSON。
- 由 `functiontest-workflow` 或 `unity-functiontest` 作为子流程调用时，复用父 Skill 传入的 timing 文件和 `parent_invocation_id`，只记录自己的原始起止时间，不扣除会话环境变量、不生成第二份 FunctionTest JSON、不单独上传；父 Skill 只在根时间计算中统一扣除过滤时间。

## 核心目标

只比较当前高亮展示的打开界面内的固定控件差异，不做像素级找不同。黑色遮罩背景层、遮罩后方界面、资源栏内容默认不参与对比。输出必须让测试能定位功能入口差异，让美术能定位布局、状态、遮挡、文字图标差异。

输出位置按调用方式区分：

- 单独调用时，写入 `Doc/AI开发文档/output/{feature_id}/ui-image-diff/`。
- 作为测试子流程调用时，写入本轮 `run_dir/ui-image-diff/`，不得写入固定的 feature 根目录，也不得覆盖其他轮次的报告。每个唯一 `UIName` 本轮最多生成一份对比报告。

## 对比边界

必须比较当前打开界面内的内容：

- 打开界面的标题栏、关闭按钮、返回按钮、帮助按钮等面板内固定入口。
- 打开界面内的顶部/中部/底部页签、固定筛选、固定说明文字。
- 打开界面的主面板边界、固定分区、固定操作按钮、固定悬浮按钮。
- 打开界面底部操作区、弹窗内底部页签栏、弹窗内按钮组。
- 控件名称、图标、数量、顺序、选中状态、禁用状态、颜色状态、尺寸间距、遮挡截断。

必须忽略：

- 当前打开界面之外的黑色遮罩背景内容，包括遮罩后方顶部栏、底部导航、主场景、侧边入口。
- 资源栏差异，包括金币、钻石、体力、货币图标、资源加号、资源数值、资源条位置。
- 截图整体缩放、平移、裁切、分辨率差异。
- 界面外背景、窗口外内容、桌面内容。
- 角色、模型、头像、动作、卡牌/道具/列表条目具体内容。
- 资源数值、等级、数量、进度、属性数值。
- 列表条目数量、列表顺序、滚动位置、动态业务选中项。

## 标准流程

1. 语义对齐：先识别当前高亮打开界面的面板边界，只在该边界内建立图A与图B的对应关系；遮罩后方内容不建立对应关系。
2. 区域扫描：按打开界面内的顶部、左侧、右侧、底部、中央主面板、固定弹层/悬浮层的顺序扫描图A和图B，列出所有固定 UI 区域。
3. 差异归并：对配对区域逐项核对控件；同一组件的文字、状态、尺寸、位置变化合并为一条，避免重复报告。
4. 排序输出：差异明细必须按影响等级从高到低展示，排序顺序固定为“高 → 中 → 低”；同一影响等级内优先展示功能入口、交互状态、结构差异，再展示视觉尺寸、间距、轻微状态差异。
5. 报告落盘：单独调用时将完整 Markdown 报告保存到 `Doc/AI开发文档/output/{feature_id}/ui-image-diff/`；测试子流程调用时保存到当前 `run_dir/ui-image-diff/`。文件名使用“界面名-效果图对比报告.md”；若界面名无法确认，使用“未命名界面-效果图对比报告.md”。子流程不得覆盖其他 run，只允许在同一 run 内更新同一 UI 的结果。

## FunctionTest 子流程约束

1. `unity-functiontest` 或 workflow 先完成识图能力和截图开关确认，再由 `unity-functiontest` 传入 `effect_diff_enabled`；本 Skill 不重复询问，也不根据模型名称自行猜测识图能力。
2. 调用前必须已经取得当前 UI 的实际截图，以及通过 `ui-quick-reference/scripts/read_ui_effect_path.py` 按当前 `UIName` 实时读取到的有效基准图路径。reference 只可提供 `UILogicManager.xlsx` 表格位置，不能提供效果图路径缓存。
3. 基准图未配置、文件不存在、表格解析失败或当前 UI 无法唯一对应时，不调用本 Skill；由父流程在 run-log 和最终报告中记录“本轮跳过效果图对比”的自然语言原因，普通功能测试继续执行。
4. 本 Skill 的差异结论是 UI 视觉证据，不自动把所有差异改写为 failed 或 Bug。只有当父流程把差异与某条 Case 的明确视觉验收条件对应，并完成 AI 归因后，才允许影响该 Case verdict 或 issue 记录。
5. 子流程报告完成后返回报告路径、当前 `UIName`、基准图路径、实际截图路径和差异结论摘要；不触发 JSON 转换或上传。

## 差异判定口径

- “缺失/新增”：固定按钮、固定页签、固定入口、固定面板只在一张图出现。
- “数量不同”：仅用于功能控件数量，例如底部导航项数量、固定按钮数量、页签数量；不要用于背包条目或卡牌数量。
- “文字图标不同”：控件文案、图标含义、入口名称不同。
- “状态不同”：选中、高亮、禁用、锁定、可点击状态不同。
- “位置尺寸不同”：控件顺序、对齐、大小、间距、固定区域占比明显不同。
- “结构不同”：固定面板分区、按钮组、导航结构有明显变化。
- “显示异常”：控件被遮挡、截断、重叠、超出面板或可读性异常。

## 报告输出要求

优先输出 Markdown 报告并写入文件；用户要求 JSON 时只在对话中输出 JSON，但仍必须额外落盘一份 Markdown 报告。Markdown 报告目录按“核心目标”和“FunctionTest 子流程约束”中的调用方式确定，报告使用以下结构：

- 对比对象：说明图A是基准图、图B是待检查图。
- 有效 UI 区域概述：分别列出图A、图B固定区域，必须覆盖底部页签/底栏。
- 忽略项：列出已忽略的动态内容。
- 差异总览：按“高/中/低”统计数量。
- 差异明细表：列包括语义区域、UI 元素、图A表现、图B表现、差异类型、影响等级、置信度、测试/美术关注点；语义区域必须限定在当前打开界面内；行顺序必须按影响等级“高 → 中 → 低”排列。
- 结论：只写明确可见问题，不猜测原因。
- 保存路径：报告末尾追加实际保存路径；单独调用时必须位于 `Doc/AI开发文档/output/{feature_id}/ui-image-diff/`，测试子流程调用时必须位于当前 `run_dir/ui-image-diff/`。

## 质检清单

提交前逐项确认：

- 已扫描图B顶部、底部、左侧、右侧四个边缘。
- 已确认只比较当前高亮打开界面，未比较黑色遮罩背景后方内容。
- 已忽略资源栏差异。
- 已单独检查打开界面内的底部页签栏和底部操作按钮。
- 已按影响等级从高到低排列差异明细，高等级差异不得排在中/低等级差异之后。
- 已将 Markdown 报告保存到本次调用方式对应的 `ui-image-diff` 目录，并在最终回复或父流程返回中提供该报告路径。
- 未报告动态列表条目数量差异。
- 未把资源数值、等级数值、卡牌数量作为固定 UI 差异。
- 每条差异都有语义区域、具体元素、图A表现、图B表现、差异类型、影响等级、置信度。
